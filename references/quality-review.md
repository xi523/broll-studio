# 成片质量检查

`validate` 只检查协议、字体和代表性排版，`render` 成功只证明可编码。它们都不会判断语义、美术或口播同步。不要把三者混为同一个“通过”。

## 先检查代表镜头，再完成整批

挑最能区分新需求的镜头：具体动作、抽象解释、两种风格差异，按任务涉及的类型选择。已授权批量时自行检查后继续，不把内部质量检查变成额外用户审批。

| 项目 | 看什么证据 | 不通过时怎么改 |
| --- | --- | --- |
| 语义 | 遮住标题，动作/关系是否仍能帮助理解；否定、条件、因果有没有变味 | 重写主体和动作，不加装饰补救 |
| 对象 | 手机尺寸可认出主体；接触点、内部结构、层级和遮挡是否成立 | 改造型/素材/景别，不只是换色 |
| 动作 | 连续播放能看出起因、作用、反应和结果；主体不凭空变换身份 | 写明确状态和时间函数，修接触/路径/落点 |
| 风格 | 同义镜头的不同版本，去掉配色后仍有运动/材质/空间区别 | 分别改机制与镜头，不复用同一动画轨迹 |
| 节奏 | 对照真实口播，动作落点跟得上；出结果后有时间识别，没有无信息等待 | 改局部事件时间和停留，不任意加速口播 |
| 文字 | 只保留必要标签；完整短语、字形、对比和安全区正确 | 语义拆句/重排，不能靠缩成小字解决 |
| 镜头组 | 连续几镜没有重复的“标题＋三卡”而语义不同；必要内容有接续 | 改重复构图与进出方式；合理信息卡不强行禁用 |
| 成片 | 实际MP4首、中、尾与转场正常，声音无突断/叠人声，导出帧数正确 | 修工程后重新看实际输出 |

检查动作启动、变化中、关键接触、结果、下镜头入口，不只看0/50/100%静帧。参考片运动明显时，比较对应连续区间。音乐和快切不能替代主体动画。

## 修改要具体

把“有点像PPT”拆成可修复的问题，例如：
- 旧：说拆解时出现三个标签。新：同一对象分成三个可辨结构层，标签跟随层。
- 旧：说调整时滑杆动，但结果不变。新：滑杆值驱动对象的真实轨迹/尺寸/颜色，变化同步。
- 旧：所有风格都从下方滑入。新：手绘裁切翻页，科技导轨吸附，暖金空间聚合；由当前语义决定适用动作。

## 通用性抽查

较大更新至少用未出现在参考中的题材试一次设计迁移，并检查同句不同风格。不能只拿旧口播改几个名词证明适配任何人。记录实际完成的是分镜检查、渲染检查还是成片视觉检查，不把未运行的方案写成已验证。

交付时可在项目 `review.md` 简记“发现的问题→修改→检查证据→仍存在的限制”。不设虚假的自动审美评分，不承诺任意脚本都一次出片。
